# 법적 요건 점검표 — 전자계약

작성: Claude, 2026-08-09 · 대상: 착한거래 전자계약(렌터카)

> **이 문서는 법률 자문이 아니다.** 기술적으로 무엇을 갖췄고 무엇이 비었는지 정리한 것이다.
> ★ 표시는 **변호사 확인이 필요한 항목**이다. 특히 주민등록번호 처리·약관 문구·위탁 관계는
> 판단이 갈릴 수 있고, 틀리면 과징금 대상이다.

## A. 전자서명법 · 전자문서법

**근거** — 전자문서법 §4①(전자적 형태라는 이유로 효력 부인 금지) · 전자서명법 §3(2020.12.10 개정으로 민간 전자서명도 동일 효력)

| 요건 | 무엇으로 충족했나 | 상태 |
|---|---|---|
| 서명자 확인 | 신분증·얼굴 촬영본 보관 + **계약서 서명자와 이름·생년 대조**(불일치 403) + 추측 불가 링크 | ✅ |
| 서명 의사 표시 | 서명 이미지(PNG) + `signedAt` | ✅ |
| **무엇에 서명하는지 명시** | 서명 화면에 계약서·계약번호·임대인·약관 버전·확인 현황을 세움 | ✅ |
| 위·변조 방지 | 원자 정규화 SHA-256 봉인 + **약관 본문 별도 해시**(문구 교체 탐지) | ✅ |
| 서명 시각·접속 정보 | `signedAt` + **서명 IP** 기록 | ✅ |
| 서명 후 변경 차단 | `status=signed` 이후 쓰기 409 | ✅ |
| 사본 제공 | 완료 화면에 **검증번호 + 봉인해시** 제시 | ✅ |
| 보존 형태(전자문서법 §5) | 「작성 당시 형태로 재현」 — 원자·A4 스냅샷을 서명 시점에 굳혀 저장 | ✅ |
| **감사추적 인증서** | 요청자·시각·IP·서명자 이력을 **문서로 발급**하는 기능 | ❌ 미구현 |
| 타임스탬프(제3자 시점 인증) | 서버 시각만 사용. 공인 TSA 미연동 | ❌ ★ |

> 상용 서비스(모두싸인·이싸인온)는 «감사추적 인증서»를 발급한다. 분쟁 시 요구받는 산출물이므로
> 데이터는 이미 다 있고 **PDF로 뽑아내는 작업**만 남았다.

## B. 개인정보보호법

### B-1. 수집·이용 (§15)

| 요건 | 상태 |
|---|---|
| 수집 «전» 동의 | ✅ 동의를 여정 맨 앞에 둠(계약 확인 → 동의 → 신분증) |
| 항목·목적·보유기간 고지 | ✅ 동의 원자에 항목·목적·보유기간·거부 시 불이익을 그대로 표시 |
| 동의 미리 선택 금지 | ✅ 기본 미선택, 「선택해 주세요」 표시 |
| 개별 동의(뭉뚱그리기 금지) | ✅ 3건을 하나씩 끊어서 받음 |
| 거부 시 처리 | ✅ 진행 차단 + 안내 |

### B-2. 제3자 제공 (§17)

| 요건 | 상태 |
|---|---|
| 받는 자·목적·항목·보유기간 고지 | ✅ **받는 자마다 따로** 표시(금융결제원 · 수납대행사) |

### B-3. 주민등록번호 (§24-2) ★

| 요건 | 상태 |
|---|---|
| 법령 근거 | 부가가치세법 §32②(세금계산서) — 계약서에 근거 명시됨 | ✅ |
| 암호화 저장 | AES-256-GCM 봉투암호화(`pii_vault`), 키는 KMS 목표 | ✅ |
| 분리 보관 | 거래이력과 분리, 직접식별정보 미보관 | ✅ |
| 보유기간 | 계약기간 + **계약 종료 후 5년**(국세기본법 §85-3) | ✅ 정책 확정 |
| **파기** | 만료분 자동 파기 배치 | ❌ **미구현 — 넣기만 하고 지우는 경로가 없다** |
| **동의서 문구 정합** | JPK 엑셀은 「계약종료일까지」인데 실제는 5년 → **문구 수정 필요** | ❌ ★ |
| **입력 화면 보호** | 뒷자리 입력 시 보안 키패드·마스킹 | ❌ 미구현 |

### B-4. 국외 이전 (§28-8)

| | 소재 | 이전 여부 |
|---|---|---|
| Firestore(계약·주민번호) | 서울 `asia-northeast3` | ❌ 없음 |
| Storage(신분증·셀피·서명·서류) | 서울 `asia-northeast3` | ❌ 없음 |
| Vercel 함수(데이터 경유) | 서울 `icn1` | ❌ 없음 |
| **Firebase Auth**(이메일·연락처·UID) | **미국** — 리전 선택 불가 | ⚠️ **처리방침 기재 필요** ★ |

### B-5. 안전조치 (§29)

| | 상태 |
|---|---|
| 접근 통제 | 회원사 API Key(해시 저장) · 본인확인 토큰 · 관리자 세션 | ✅ |
| 저장 암호화 | AES-256-GCM 봉투암호화 | ✅ |
| 전송 암호화 | HTTPS 전 구간 | ✅ |
| **공개 노출 차단** | Storage 버킷 **public-access-prevention enforced** + 규칙 전면 거부 | ✅ |
| 접속 기록 보관 | `audits` — 발급·서명·거부 기록 | ✅ |
| 최소 권한 | 서비스계정에 Firestore·Storage 권한만 | ✅ |
| **관리자 마스킹 뷰** | 관리자도 원문 자유조회 불가(§10 불변식) | ❌ 미구현 |
| **접근기록 위·변조 방지** | 감사로그 WORM | ❌ 미구현 |

### B-6. 위탁 (§26) ★

| | 상태 |
|---|---|

## F. 반드시 변호사에게 확인할 것 ★

1. **주민등록번호를 착한거래가 보관하는 구조가 맞는가** — 세금계산서 근거는 렌트사에 있는데 수탁자가 보관하는 형태
2. **위탁계약 생략이 가능한가** — 프리패스·JPK·착한거래가 «같은 회사»인지 법인 기준으로
3. **동의서 문구** — 보유기간·제3자 제공 범위·위치정보
4. **약관 문구 신설분** — 규칙을 계약서에서 약관으로 옮길 때 새로 쓰는 문구
5. **전자서명만으로 충분한가** — 렌터카 계약에 추가 요건(대면 확인 등)이 있는지
6. **개인정보 처리방침** 전문
