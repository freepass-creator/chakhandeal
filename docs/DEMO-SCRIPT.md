# 시연 각본 — 착한거래 (chakhandeal)

버전: 1.0 · 2026-08-03 · 전 동선 E2E 리허설 완료 기준

## 준비 (시연 직전)

- 서버: `cd D:\dev\chakhandeal ; npm run dev`
- 폰 시연: `cloudflared tunnel --url http://localhost:3000` → https 주소를 폰에서 열기 (카메라는 https 필수)
- 데이터 초기화 필요 시: 서버 재시작 (mock 스토어 = 서버 메모리)
- PC에서 보면 폰 프레임, 실폰에서 열면 전체 화면 (자동)

## 등장 인물·코드

| 구분 | 값 | 용도 |
|---|---|---|
| 회원사 로그인 | 로그인 화면 칩 「테스트렌탈 (렌탈)」·「해피펫분양 (반려)」 | 클릭 즉시 로그인 |
| 거래코드 | 1001 테스트렌탈(렌탈) · 2001 해피펫분양(반려) | 손님 동의 대상 |
| 샘플-깨끗 | 김신규 | 어디서나 「신규」 |
| 샘플-렌탈 위반 | 홍길동 | 렌탈 미납 이력 |
| 샘플-반려 위반 | 김반려 | 분양 후 유기 이력 |

※ 본인확인 샘플 칩은 업종에 맞게 자동 노출 (반려면 김반려, 렌탈이면 홍길동)

## 동선 1 — 손님 동의 (핵심, 2분)

1. 홈 → 「동의 및 내 상태 보내기」
2. 코드 칩 2001 해피펫분양 → 본인확인 → 샘플 「이력 있음 · 김반려」
3. 동의 체크(문구: 동의 기록과 내 상태 검증이 함께 전달) → 서명 → 완료
4. **멘트**: 손님은 동의 한 번으로 끝. 상태 검증이 회원사 콘솔에 자동 전달 — 별도 절차 없음
5. 완료 화면: 동의번호 + 상태 검증 번호 + 「처음으로」

같은 동선을 김신규로 반복하면 「신규」 케이스 (깨끗한 손님은 불리하지 않음 강조)

## 동선 2 — 내 상태 보기 (1분)

1. 홈 → 「내 상태 보기」 → 업종 「반려·분양」 선택
2. 본인확인 김반려 → 내 상태 「기록 있음」 확인
3. 「내 상태 보내기」 → 링크 생성 → 카톡·문자 공유 (또는 링크 복사)
4. 받은 링크(/v)를 다른 기기·시크릿창에서 열기 → 실시간 상태 확인
5. **멘트**: 캡처는 인정 안 됨 — 링크가 실시간 원본. 7일 유효

## 동선 3 — 회원사 콘솔 (2분)

1. 홈 하단 「회원 로그인」 → 칩 「해피펫분양 (반려)」 클릭 (즉시 로그인)
2. 「검증 수신」 탭: 방금 손님 동의 건이 자동으로 쌓여 있음 확인
3. 「거래 위반」 탭: 위반 등록 시연 — 이름·생년월일·유형·사유 입력 → 등록
4. 등록 직후 그 인물로 「내 상태 보기」 다시 → 즉시 「기록 있음」 반영 (실시간성 강조)
5. **멘트**: 등록은 동의받은 손님 + 중대 위반만. 조회가 아니라 손님이 자기 상태를 스스로 증명하는 구조

## 핵심 멘트 (반복 강조)

- 검색·블랙리스트 아님 — **손님이 자기 정보를 스스로 증명**하고 필요한 상대에게만 보여줌
- 동의 한 번 = 동의 기록 + 상태 검증 자동 전달 (손님 추가 행동 없음)
- 업종 분리 — 반려 증명엔 반려 기록만 (렌탈 이력이 반려 분양에 불이익 안 줌)
- 캡처 무효 — 링크만 실시간 원본

## 주의

- 서버 재시작하면 시연 중 만든 데이터 사라짐 (씨앗 데이터는 유지)
- 터널 URL은 실행마다 바뀜 — 시연 직전에 띄우고 폰에 미리 열어둘 것
- PASS·통신사 인증은 연동 전 (샘플 통과) — 질문 나오면 "실연동 예정" (docs/INTEGRATIONS.md)
