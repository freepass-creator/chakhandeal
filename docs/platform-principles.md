# 착한거래 플랫폼 원칙 — 자기정보 증명 (Cross-Vertical)

버전: 0.3 · 2026-07-24 · rentsafe-pro

## 한 줄 정의 (전 업종 공통)

> **내가 쌓은 신뢰를 내가 확인하고, 필요한 상대에게만 직접 증명하는 서비스**  
> (검색·블랙리스트·중개 마켓이 아님)

당근온도를 **본인이 열어 상대에게 제출**하는 모델. 상대가 나를 이름으로 뒤지지 않는다.

---

## 이중 필터 (사업자 심사 절차)

사업자는 플랫폼이 사람을 “불량”으로 낙인찍지 않으면서도, **필수 절차 미이행**으로 걸러낼 수 있다.

| 단계 | 요청 | 통과 | 미통과 시 |
|------|------|------|-----------|
| **1차** | 착한거래 **동의** (앱에서 본인확인·목적별 동의) | 동의 완료 | 해당 건 신청 종료. **부정적 이력·블랙리스트 생성 안 함** |
| **2차** | **검증 링크 전달** — 앱에서 만든 **살아 있는 확인 URL**을 이용자가 **카톡·문자**로 사업자에게 직접 전달 | 사업자가 링크를 열어 서버 기준 결과를 확인 | “필수 절차 미완료”로 심사 종료. **미전달을 불량 이력으로 저장·공개하지 않음** |

```text
[링크] → 1차 동의 (앱 내)
           ├─ 거절/이탈 → 걸러짐 (낙인 없음)
           └─ 동의 완료
                → 앱에서 검증 링크 생성
                → 이용자가 카톡/문자로 사업자에게 링크만 전달
                     ├─ 안 보냄 → 걸러짐 (낙인 없음)
                     └─ 전달됨 → 사업자가 URL을 열어 확인 → 상담·최종 결정
```

### 왜 “증명서”가 아닌가 (중요)

- **파일·캡처·복사 문구·PDF**는 위조·조작·재배포가 쉽다.
- 신뢰의 근거는 **문서가 아니라 서버가 지금 보여주는 페이지**다.
- 따라서 2차 전달물은 **검증 링크만** 허용한다. 상태·점수·진위번호를 메신저 본문에 넣지 않는다.
- 화면 캡처·“확인서 복사”로 대체 제출하는 UX는 금지한다.

### 검증 링크 전달 방식

| | **사업자 코드 지정** | **외부 전달 (카톡·문자)** |
|--|----------------------|---------------------------|
| 이용자 행동 | 생성 시 분양/회원 **코드**를 넣음 | 생성 후 **URL만** 카톡·문자로 보냄 |
| 사업자 측 | **로그인 콘솔**에 수신 목록으로 보임 | 받은 **검증 링크**를 열어 확인 (로그인 없이도 열람 가능) |
| 앱 역할 | 해당 사업자 코드에 기록 귀속 | 공유용 **URL만** 제공 (메신저 대행 발송 아님) |

- 코드 지정 = “이 사업자 건으로 귀속”. 콘솔에서 조회 가능.
- 카톡·문자 = “이용자가 직접 전달하는 채널”. **링크만**으로 진위 확인.
- 보통 **둘 다** 쓴다: 코드로 귀속(콘솔) + 카톡으로 안내 링크.
- 검색·블랙리스트는 없음. 이용자가 연 것만 해당 사업자/링크 수신자가 본다.

- 1차만 하고 2차를 안 하면: **동의는 됐으나 검증 미전달** (해당 건만 종료 가능).
- 표현 금지: “문제 인물”, “블랙리스트 의심”, “안 보냄 = 이력 있음”.
- 권장: “필수 심사절차 미완료로 이번 신청을 진행할 수 없습니다.”

펫·렌트·펜션·식당 모두 동일한 1·2차 구조. 업종별로 동의 문구·사후 이행만 달라진다.

| 원칙 | 의미 |
|------|------|
| 검색 금지 | 사업자가 이름·전화·생년월일로 이용자 조회 불가 |
| 본인 주도 제출 | 검증 링크는 이용자가 생성·전달 |
| 링크만 전달 | 캡처·복사 문서·오프라인 “증명서”로 대체 제출 금지 |
| 건별 동의 | 포괄 “모든 사업자 공개” 동의 없음 |
| 사실 기록만 | 주관 별점·미확정 신고·자유 비난 없음 |
| 신규 = 신규 | 이력 없음 ≠ 낮은 점수 / 불량 |
| 미제출 ≠ 블랙리스트 | 해당 건 심사 미완료일 뿐, 부정적 이력 생성 금지 |
| 자동 거절 금지 | 점수만으로 승인/거절하지 않음 |
| 보증 없음 | 미래 행동·적합성을 플랫폼이 보증하지 않음 |

**렌탈 기존 MVP**의 “이름+생년월일 조회”·“상태확인서 복사”는 본 원칙과 충돌한다.  
고도화 방향: **조회·문서 복사 → 본인 검증 링크 전달(건별)** 으로 수렴. 사업자 콘솔은 “검색”이 아니라 “수신된 검증 기록 열람 / 이행 사실 등록”만 제공.

## 검증 페이지에 보이는 내용 (공통 골격)

**링크를 열었을 때(서버 응답):** 본인확인 여부, 점수 또는 `신규`, 활동 요약, 중대 확정 위반 건수, 이의제기 여부, 생성·유효기간  

**비공개 기본:** 주민번호, 상세주소, 전화 전체, 과거 상대 개인정보, 사진 원본 전부, 자유 비난, 미확정 신고  

**신규 표시:** `책임점수: 산정 전 / 상태: 신규 / 부정 이력 없음` — 이력 없음 ≠ 신뢰 낮음  

**공유 메시지:** URL(+상대 상호명 정도)만. 상태·점수·번호를 본문에 넣지 않음.

---

## MVP 우선순위 (플랫폼)

1. 사업자 링크 발급  
2. 이용자 본인확인 + 목적별 동의  
3. 검증 링크 생성 → 카톡·문자로 URL만 전달  
4. 사업자 기간 한정 열람  
5. 사후 이행 기록 + 본인 이력 화면  
6. 이의제기  

**제외:** 검색, 블랙리스트, 주관 별점, 자유 부정 후기, AI 적합성 판정, 점수 자동거절, **다운로드·복사 가능한 “증명서” 문서**
